▶ How This Was Built (System Design & Extension Guide)

🧠 The System Prompt (Claude's "Brain")

The assistant uses a specialized system prompt that acts as an expert project prioritization consultant. Here's what makes it work:

Role: Executive project prioritization consultant
Input: Free-text project descriptions
Analysis Criteria: Impact (strategic alignment, revenue, blockers), Urgency (deadline proximity, risk), Feasibility (resources, dependencies), Effort (team size, complexity)
Output: JSON with ranked projects, scores (0-100), and executive reasoning
Tone: Professional, data-driven, no fluff

Key Features:

  • Extracts priorities using a weighted scoring model
  • Identifies dependencies and blockers
  • Flags unrealistic timelines or resource constraints
  • Handles incomplete information gracefully
  • Returns reasoning so users understand *why* each rank

🎨 UI/UX Design Choices

Why this layout matters:

  • Two-column grid: Input on left, results on right—users see cause and effect in one view
  • Ranked badges (1, 2, 3): Color-coded and visually prominent; executives scan this first
  • Score badges: Simple numeric scores (92/100) are instantly understood and memorable
  • Reasoning text: One-line executive summary—why this project got this rank
  • Hover animations: Cards lift on hover to signal interactivity and polish
  • Loading spinner: Clear feedback during API call; users know something's happening
  • Empty state: Inviting empty view with clear next steps (not intimidating)

🔌 How the API Integration Works

This app calls Claude's API in real-time using fetch() to api.anthropic.com/v1/messages. No API key is needed—it's handled by the backend.

// User clicks "Prioritize Now"
1. Parse projects from textarea
2. Send to Claude with system prompt
3. Claude returns ranked JSON
4. Render results with animations
5. Show error if API fails

Error Handling: If Claude can't parse projects or the API fails, a friendly error message appears. Users can retry.

📐 Scoring Logic (Inside the Prompt)

The system prompt asks Claude to score each project on these dimensions:

  • Impact (40%): Does it unblock other work? Revenue impact? Strategic alignment?
  • Urgency (30%): Deadline proximity? External dependencies? Compliance risk?
  • Feasibility (20%): Do we have the resources? Are dependencies resolved?
  • Effort (10%): Is it realistic? Any hidden complexity?

Claude weights these and produces a final 0-100 score, then ranks from highest to lowest.

🛡️ Edge Case Handling

Empty input: If textarea is empty, show a validation error.

One project: Still works—user gets one result with reasoning.

Contradictory data: "High impact but due yesterday." Claude flags the contradiction and explains the reasoning.

Missing info: "Deadline unknown, team size unknown." Claude says "Based on available info, best guess is..."

Unclear descriptions: Claude asks for clarification in the reasoning and gives a lower confidence score.

💡 Pro Tips for Users

  • Include deadlines, team size, and business impact—Claude ranks better with more info
  • Mention dependencies: "Blocked by Project A" helps Claude understand bottlenecks
  • Use it for strategic planning (Q3 roadmap) or tactical fire-fighting (urgent bugs)
  • Re-run with new info as situations change—roadmaps are living documents
